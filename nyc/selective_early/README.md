# 第 2 分钟选择性加急告警验证

## 研究决定

主方案为非潮汐站在总 10% 的事件误报预算中为第 2 分钟留 2 个百分点，第 5、8 分钟使用剩余名额。2%是相对于全部未升级事件的门槛选择预算，不是只给总事件的2%报警。第2分钟必须有可评分读数且水深较首湿上升，使用既有的涨速外推值与潮汐属性评分。普通复查仅在未提前告警时进行，保留原来的观测资格要求。潮汐站全部沿用5/8分钟策略。研究前确定1%、3%仅用于敏感性分析。

主要后期测试是 2026-07-01 至10-26，其中非潮汐站429场（升级148，未升级281）。固定相同的28次误报时，原策略及加急主方案均及时捕获10场，加急主方案总共捕获49场、原方案38场。两者及时命中的是同一组事件。若改用历史门槛，原策略及时捕获18场、误报52场；加急方案21场、误报56场。较早测试期为2026年上半年，共47个非潮汐正例，在等误报预算下原策略和加急方案均没有五分钟及时命中。未见跨时段的稳定改善。保留现行产品默认策略。

同误报口径下的19次加急告警中，14场最终升级，5场未升级。14场中有13场的保守提前量不足5分钟；唯一本来得及的事件也被原策略及时捕获。2分钟处的急涨分数容易找出即将升级的过程，但为处置预留的时间常常太短。1%或3%的加急预算后期及时命中分别为10场和11场。历史样本已用于以往多次探索，所报告的时间块不确定性不能替代未来盲测。
截至2026-11-12复查纽约市事件 API，仍为3581行，最晚事件开始为2026-10-26 14:43:29 GMT；该入口尚无更新时段可作独立测试。

## 复跑

在此目录使用 ../requirements.txt 安装依赖，执行 python selective.py 和 python lead_audit.py。Python 3.14 环境实测；数据是项目的冻结快照。first_look.py 复用既有的共同队列、特征与时序划分。脚本复用不同检测时刻的既有拟合方法；不向模型提供测试标签。matched 是用测试阴性事后比较同一误报数，固定事件散列处理并列。frozen 仅使用先前验证期阴性设置门槛，同分同判。后续阶段从未早报阴性中选择阈值，使两次预算之和受同一上限控制。

- result/metrics.csv：两个时期、两种阈值评价方式、五个策略、三个站点分组的全部结果。replace 表示仅在非潮汐站以2/5分钟替代5/8分钟。timely、late、miss 之和为 pos。
- result/thresholds.csv：历史及事后匹配阈值。阈值 inf 表示该策略/分组没有提前发警通道。
- result/paired_changes.csv 与 event_decisions.csv：主加急策略相对原策略逐例新增、失去的及时命中和误报。
- result/fixed_threshold_ci.csv：冻结模型与门槛，测试期按全城时间块配对重采样的非潮汐差值区间。不适用于匹配误报口径。
- result/lead_profile.csv：同一批告警在要求1、3、5、8、10分钟提前量时的表现；0表示所有报中的升级。5分钟仍是主指标。
- result/early_alarm_breakdown.csv：主方案逐个提前告警的事后核查。

数据来自 FloodNet (New York University and The City University of New York) 与 NYC DEP。
