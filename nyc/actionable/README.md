# 首湿后逐读数的积水升级检测器（研究候选）

正式产品仍使用 midterm-freeze-v1。本候选用于回答：提前到每次新读数都判断，用过去曲线的形状打分，能否在相同误报数下增加至少提前 5 分钟的命中？

## 运行一个真实例子

从本目录执行。评分仅需 Python 3 标准库。

    python3 detector.py --site non_tidal --readings '[[0,0.63],[120,2.52]]'

这是布鲁克林 Lee Ave / Middleton St 在 2026-08-23 的前两笔湿读数，单位为秒、英寸。只传第一笔时结果为 null，两笔时在首湿后 2.0 分钟发警。此后第 8 分钟仍低于 4 英寸，第 9 分钟首次测得 4.09 英寸，故可确认的提前量为 6 分钟。此例按新模型使用历史门槛后独有的及时命中挑选，只用于解释。实际为一场事件连续传入同一条曲线的前缀；返回值为已触发的最早时刻，null 表示截至输入末端没有发警。模型要求已知潮汐属性。

## 回测

在包的根目录安装 nyc/requirements.txt 后运行：

    python -m pip install -r nyc/requirements.txt
    python nyc/actionable/experiment.py

训练与校准的日期、输入和比较方式详见 protocol.md 和 nyc/first_look.py。测试事件不参与训练。metrics.csv 中 timely、late、miss 加总为 pos，fp 为未升级事件中的误报数。decisions.csv 是逐场对照，空告警时间表示未发警。candidate.json 是对后期测试使用的历史模型，在看本候选结果前确定了模型设计。历史数据已参与早先其他实验。

| 测试期和口径 | 正式时刻 5/8 参考 | 新模型逐读数 | 简单外推逐读数 | 新模型仅 5/8 |
|---|---:|---:|---:|---:|
| 2026-07 至 10 月，全网 296 次升级，同为 68 次误报 | 79 | 66 | 64 | 65 |
| 同期非潮汐 148 次升级，同为 28 次误报 | 10 | 15 | 18 | 12 |
| 2026 上半年，全网 120 次升级，同为 45 次误报 | 43 | 41 | 38 | 38 |
| 同期非潮汐 47 次升级，同为 25 次误报 | 0 | 0 | 2 | 0 |

表内是及时命中数，使用事后对齐的误报数；上半年的 5/8 参考按该时段的历史重新拟合。固定历史门槛后，后期非潮汐站新模型及时 15/148、误报 22/281，现有产品及时 15/148、误报 49/281，两者各有 6 场独有及时命中。同期全网新模型及时 81/296、误报 98/689，正式产品及时 97/296、误报 121/689。较低误报与较低全网召回同时出现。逐读数模型未达到事先约定的替换条件，当前冻结产品与其独立验证协议均沿用原版。
