打开 [FloodNet independent validation](https://github.com/Owen2005-brilliant/smart_city/actions/workflows/independent-validation.yml)，选择 **Run workflow** 并使用 main 分支。任务会检出本冻结标签，通过历史自检后下载官方数据并评分。运行摘要列出新增数、及时命中与误报；在 **Artifacts** 下载报告、逐事件表和两张输入快照。下载包保留 30 天，有引用需求时请自行存档。

## 一条命令

在仓库根目录运行（Python 3.9+ 与 curl；本入口不需要安装模型训练依赖）：

    python3 nyc/prospective/validate_new.py

如需在新电脑上固定到发布时的源码，先执行：

    git clone --branch midterm-freeze-v1 https://github.com/Owen2005-brilliant/smart_city.git
    cd smart_city
    python3 nyc/prospective/validate_new.py

程序从 NYC Open Data 下载完整的两张官方表，并用计数和更新版本检查导出是否完整。源服务暂不可用或导出期间变动时，命令会报错，可重新运行。缺少新事件是正常状态。输出位置为 nyc/prospective/runs/official/ 下的快照目录，重复运行同一快照不会重复计数。

离线回放（目录内放两张完整的官方导出文件 events.csv、sites.csv）：

    python3 nyc/prospective/validate_new.py --local-dir /path/to/full-export --out /path/to/reports

离线结果单列于 offline/。归档目录自带原始输入文件，因而也可以把已有 official/ 快照作为 local-dir 重放。每次输出是相对冻结清单的**累计**验证，不跨快照相加。官方后续修订可能改变新事件的结局，引用结果时请记录快照目录名、数据 SHA-256 和取得时间。保留各次快照可追查修订。运行报告默认不进入版本库。

## 锁定的规则和口径

- **正式产品**：首个实测深度超过 10 mm 后第 5 分钟判断；未发警且有新读数，第 8 分钟复查。两次均止于首湿后第 35 分钟。正涨速外推特征、两阶段系数、首次判断的额外门槛、潮汐／非潮汐分类与各自告警阈值均已固定在 frozen_models.json。默认模型对应 nyc/model.json。
- **主要评价**（product）：沿用已有 859 场测试的入组规范。第 5 分钟仍湿、最近读数至多 3 分钟、此前未观测到 4 英寸；预测窗须有后续证据、相邻支持点缺口最多 5 分钟，若提前结束则末读数须为零。对照为单次简单涨速外推，预计窗末达到 4 英寸即告警。只报告两种冻结规则的实际误报率，不在新批次反求等误报阈值。
- **次要评价**（common）：固定真值为首湿后 35 分钟内是否达到 4 英寸。对完整可核验事件评分，包含首判前已越线和读数不足而未能出分的事件。并列报告已发布产品、重建研究的 5/8 分钟及 2/5 分钟策略、仅非潮汐站开放的第 2 分钟加急候选，以及简单外推。加急预算为历史非潮汐未升级事件的 2 个百分点，总历史预算约 10%；使用主实验的冻结门槛。研究 5/8 模型与正式产品的校准分母不同，需按 cohort、policy 对齐比较。
- **主要指标**：及时命中数 / 全部可评分升级事件；及时表示发警到首次越线前最后一个低于阈值的读数至少 5 分钟。另报事件误报率 FP / 未升级事件数、报晚数和漏报数。干燥时间无完整记录，不能据此估计全天候误报率。分母为零输出 JSON null。全网、非潮汐、潮汐、冻结部署表未收录的站点分别统计。
- **数据边界**：旧事件键的修订与缺失单独计数，截止日前回填不入组。新键如与同站旧事件结束时间完全相同，列为可能的修订。冻结站点沿用冻结潮汐属性，如新旧冲突暂不评；新部署须有明确官方属性。缺字段、非法曲线、提前退水无零值、未知站点等在清单中留痕。精确重复键折叠，冲突重复键中止运行。仍可能存在事件起止日期同时被改写且无法从两个导出表识别的情况。
- **解释**：已有数据的回放、构造样本和空报告只能证明流程工作。真正的独立结果需要冻结后发生、后来进入官方复核库且符合观测要求的事件。滚动查看的累计结果仅作描述性报告，不因某一批次有利就宣布模型优越。后续改规则应另开版本和新的独立时段。

## 如何看报告

- report.json：冻结配置与输入哈希、官方表版本、截止、数据审计计数、分组的分子与分母。status 为 no_new_events、no_scorable_events 或 scored；两套队列各自可能无可评分事件。
- cohort.csv：冻结底表中不存在的事件逐条列出，含回补、待核验及两种队列的入组／排除原因。
- predictions.csv：按站点事件、队列、策略列出是否升级、告警分钟、保守提前量和是否及时。同一事件的不同策略记录用于配对，不应相加为事件总数。
- events.csv、sites.csv：本次使用的原始导出；数据归属 FloodNet（NYU、CUNY）及 NYC DEP。[事件数据](https://data.cityofnewyork.us/d/aq7i-eu5q) · [站点元数据](https://data.cityofnewyork.us/d/kb2e-tjy3)

从根目录运行离线自检：

    python3 -m unittest discover -s nyc/prospective -p 'test_*.py'

测试检查既有 859 场正式队列的指标、985 场共同队列研究策略的逐场决策，另检查去重、隔离修订及补录、空分母和重复运行。冻结清单中的文件若有修改，独立验证命令会停止并指出对应文件。
