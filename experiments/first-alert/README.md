# 非潮汐站第 5 分钟首报门槛优化实验

## 问题与结果

等到第 8 分钟再报，哪几场真的会因此来不及？后期非潮汐站有 331 场可评分积水，67 场升级。原规则在相同 26 次误报下及时报中 10 场，另有 28 场报晚。其中 23 场即使第 5 分钟报警也不足 5 分钟提前量；余下 5 场在第 5 分钟还有时间，却到第 8 分钟才报。这五场是仅更改首报门槛能够直接挽回的报晚案例，另有 18 场漏报在第 5 分钟仍有时间。

| 第 5 分钟非潮汐首报策略 | 后期同为 26 次误报，及时命中 / 67 | 前期同为 24 次误报，及时命中 / 11 | 后期直接沿用产品数值门槛：及时命中 / 误报 |
|---|---:|---:|---:|
| 原版，高首报门槛 | 10 | 0 | 15 / 49 |
| 所有非潮汐站统一放宽 | 12 | 0 | 16 / 52 |
| 用当前涨速估算剩余时间，时间刚好够时放宽 | 10 | 0 | 16 / 51 |
| 学习哪些事件等不起，只对高分事件放宽 | 12 | 0 | 15 / 49 |

“同为 26 次误报”使用测试阴性对齐比较排序；“直接沿用产品门槛”回答只改首判逻辑、未再校准时的表现。两列的数值不能混用。主测试的全网另按 66 次误报匹配，四条规则均为 83/192。按组分别匹配预算解释了子组与全网的差异。

后期学习方案给 39/331 个非潮汐事件放宽首报。在同等误报下，新增两场及时、没有失去原来的及时命中。其中布鲁克林 Lee Ave / Middleton St（7 月 18 日）和皇后区 Norton Ave / Beach 45th St（9 月 26 日）均从第 8 分钟移到第 5 分钟发警，保守提前量分别由 2:00、2:01 增至 5:00、5:01。两场也都被统一放宽规则挽回。以 14 个天气时间块为单位做 1,500 次配对重采样，学习方案相对原版的及时召回率差为 +2.99 个百分点，95% 百分位区间约 −2.86 至 +5.56 个百分点。模型固定，重采样仅反映测试时段组成变化。

有提前量升级的正例不等于“等不起”的训练标签。每个划分的早期训练集中，非潮汐站满足“第 5 分钟及时，等到第 8 分钟会报晚或无法复查”这一严格标签的仅 1 场，模型主要借用潮汐站的历史。后期测试中的此类非潮汐事件有 12 场，时间窗法选中 1 场，学习法选中 5 场。放宽资格不等于最终告警。

敏感性分析中，按后期非潮汐阴性事件的 5%、10%、15% 匹配误报预算时，原版及时命中分别为 5、10、13 场，学习法为 4、12、13 场。各自使用更早验证期校准门槛后，非潮汐站学习法与原版都是及时 16 次、误报 51 次。历史结果不满足预定替换条件。继续使用已冻结的 5/8 分钟检测器；本轮学习法可作为探索候选。

## 复现

用 Python 3.14 在本目录运行：

    python -m pip install -r ../../nyc/requirements.txt
    python experiment.py ../../nyc --out rerun
    python check.py rerun

protocol.md 记录运行前确定的规则和替换标准；result/metrics.csv 给出全部预算、分组、时期；result/paired.csv 记录新增与失去的及时命中；result/diagnostics.csv 检查门槛放宽覆盖的样本；result/decisions.csv 保留事件标识、首判信号、两阶段告警时刻、真实时间余量与是否及时；result/intervals.csv 给出配对重采样区间。提前量为告警到越线前最后一个低读数的时间，两次采样之间的真实越线时刻未知。所有结论均来自前几轮已研究过的事件。
 
来源为 FloodNet（NYU、CUNY）与 NYC DEP 的[事件表](https://data.cityofnewyork.us/d/aq7i-eu5q)及[站点表](https://data.cityofnewyork.us/d/kb2e-tjy3)。[正式冻结版](https://github.com/Owen2005-brilliant/smart_city/tree/midterm-freeze-v1)。
